# AWUS036ACH 接続補助（任意・実験的）

[English](BSS_HELPER_EN.md) | **日本語**

`ldn_bss_seed` はLinux側の接続先情報を補う任意のカーネルモジュールです。同梱Cソースを利用するPCでビルドします。Wi-Fiドライバを置き換えるものではありません。

**対象は Linux の AWUS036ACH（RTL8812AU）＋ `rtw88_8812au`。ACHM / `mt76x0u` や旧 `88XXau` は対象外です。** Windowsから使う場合は無線機を所有するLinux/WSL側で準備します。WSLのUSB割当て・対応カーネル構築はこのツールでは行いません。

## 何をするか

選択した部屋のBSSID・SSID・チャンネルから Probe Response 相当のデータを作り、PC内部の `mac80211` 受信処理へ渡して一時的な接続先情報（BSS）を作ります。その応答を電波へ送信するものではありません。ただし接続準備の通常のWi-Fiスキャン・認証通信は行います。鍵の代替・認証の省略・交換/保存処理の代行はしません。

通常経路で接続できる場合には不要です。既に同じBSSID・SSID・周波数のBSSがあれば、モジュールを読み込まず通常の認証へ進みます。標準経路が失敗したら無断で補助へ切り替える方式ではなく、**利用者が選んだ場合だけ**使用します。

## 導入：そのPCのカーネル向けにローカルビルド

1. [利用手順](USER_GUIDE.md)に従い `sh scripts/setup_za.sh --live` でPython環境を準備します。
2. OSのパッケージ管理で **実行中カーネルと一致するヘッダー**とビルドツールを用意します。`uname -r` と `/lib/modules/$(uname -r)/build/include/config/kernel.release` が一致する必要があります。Ubuntu/Debianなら通常 `build-essential` と `linux-headers-$(uname -r)`、Arch系なら実際に起動しているカーネル用のheadersパッケージと `make`、GCCまたはClang/LLDです。CachyOSのClangカーネルはClang/LLDを使用します。違うカーネルのheadersで代用しないでください。
3. 一般ユーザーで実行します（ビルドに `sudo` は不要）。

```sh
sh scripts/setup_bss_helper.sh
```

既定の出力は展開フォルダー内の `bss-helper/<実行中カーネル版>/` です。既存フォルダーは上書きしません。別の新規出力先を引数で指定できます。

wheelから導入した場合も同じ処理を使えます：

```sh
zatrade bss-helper build --output "$HOME/za-bss-$(uname -r)"
zatrade bss-helper check --bundle "$HOME/za-bss-$(uname -r)"
```

ソースはPythonパッケージ内に含まれ、開発者のworkディレクトリーや過去の `.ko` は不要です。ビルドはダウンロード・OSパッケージ導入・`insmod`・`modprobe`・DKMS設定・自動読み込み設定を行いません。`BUILD.json` と `.ko` を一組で保持します。カーネル更新後は新しい版で再ビルドして選択し直してください。

## アプリで使う

- Linux GUIの「このPCのWi-Fi」で専用のAWUS036ACHを一覧選択。
- 「詳細設定」→「AWUS036ACH接続補助（任意）」の「参照」で、上で作ったフォルダーを選択。
- その選択中だけ既存インターフェイスの再利用を使用。解除すれば従来経路に戻ります。アプリを再起動すると選択は解除されます。
- 通常の鍵・8桁パスワード・送受領ファイルを設定して開始します。PA9編集だけなら補助も管理者権限も不要です。

CLIの `trade` / `handshake` / `probe` / Linux側 `relay-serve` には `--bss-helper /絶対パス/ビルドフォルダー` を追加できます。`--phy` と `--interface` はそのPCの専用アダプターを指定します。補助を使うときは存在する物理インターフェイスの再利用となり、`--no-single-interface` とは併用できません。Relayへ接続するクライアント側に指定しても転送されず、明示エラーになります。

実際の使用時は、通常の無線操作権限に加え、カーネルモジュールを読み込めるLinux管理者権限が必要です。アプリは自動昇格しません。Secure Boot/lockdown/署名必須ポリシーに拒否された場合は停止します。**保護を無効化する自動処理や強制読み込みはありません。** このビルダーはモジュール署名・鍵登録をしないため、署名必須の環境はこの手順だけでは利用できません。

## 後片付け・制約

- 単一のグローバルモジュールロックを取得。既にロード済みの別所有者のモジュールを借用・削除しません。
- 選択したインターフェイスの同一性、driver、カーネル版、ELF情報、ビルド記録のSHA-256を確認します。ローカルビルド記録は第三者の署名証明ではありません。他人から渡されたバイナリ/記録を信頼せず同梱ソースからビルドしてください。
- 対象のscan-startイベントを確認してから読み込み、scan完了と同じBSSID/SSID/周波数を検証して通常の接続へ進みます。対象チャンネルは標準探索の1/6/11です。
- 1回の開始で補助を使う接続は1試行。通信worker終了後に、自分が読み込んだモジュールだけ非強制で取り外します。取り外しに失敗したら成功表示にはせず、所有権と復旧状態を保持します。無理に次の交換を始めないでください。
- プロセス強制終了・電源断時の自動復旧daemonはありません。モジュールが残っていると次回は拒否します。OS管理者が状態を確認し、使用中でないことを確認して通常の `rmmod ldn_bss_seed` を行う必要があります。他プロセス所有のものを削除しないでください。
- **この統合経路での実機交換・保存・復旧は未検証です。** 過去の成功構成・接続だけの試験と、この配布版の根拠は[検証情報](TESTING.md)で区別しています。
