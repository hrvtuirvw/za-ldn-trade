# za-ldn-trade — 使い方

[English](USER_GUIDE_EN.md) | **日本語** · [ホーム](../README_JA.md) · [困ったとき](TROUBLESHOOTING.md)

まずオフラインでPA9を作成・編集し、無線が必要な場合だけ接続を準備します。起動・作成・保存だけでは鍵を読まず、無線通信も始まりません。

[導入](#導入) · [最初のファイル](#最初のファイルを作る) · [表示と操作](#表示言語と操作) · [無線](#無線の準備) · [交換](#交換する) · [停止・保存](#停止と結果の確認)

## 導入

- **オフラインGUI/CLI：** Python 3.10以上。GUIにはTkとデスクトップ画面が必要です。
- **無線処理：** Linux/Python 3.12以上、専用の対応Wi-Fi、driver/firmware、`iw`、`ip`（iproute2）、`nmcli`（NetworkManager）、`sysctl`・`pkill`（procps）、無線操作権限が必要です。
- ソースZIP／wheelにはPythonを同梱しません。初回の依存導入はインターネット接続が必要な場合があります。
- ローカル実行確認はLinux/Python 3.14.8です。Windows/WSL・他Python・この版での実機交換／保存／復旧は未検証です。[検証情報](TESTING.md)。

### ソースZIP：Linux

ZIPをユーザー所有のフォルダーへ展開し、そこをターミナルで開きます。OS側でPython・venv・Tkを用意してください。Debian/Ubuntuは通常`python3-venv`・`python3-tk`、Arch系は`python`・`tk`です。

```sh
sh scripts/setup_za.sh
sh scripts/start_za_gui.sh
```

setupは展開先の`.venv-za`とPython依存を準備します。ドライバ・OSパッケージ・無線設定は変更しません。Tkがない場合はOS側で導入し、再実行してください。

### ソースZIP：Windows

Python 3.10以上をTcl/Tk・Python launcher付きで導入し、展開フォルダーのPowerShellで実行します。

```powershell
py -3 -m venv .venv-za
.\.venv-za\Scripts\python.exe -m pip install -r requirements-za.txt
.\Start-za-ldn-trade.cmd
```

以後は`Start-za-ldn-trade.cmd`をダブルクリックします。オフライン編集のために管理者として起動する必要はありません。PowerShellの実行ポリシー変更もこの手順には不要です。

### Wheel

ダウンロードしたwheelを専用の仮想環境へ導入します。PyPI公開は前提にせず、`VERSION`を実ファイルの版番号へ置き換えてください。TkはPython／OS側で別途必要です。

Linux（POSIXシェル）：

```sh
python3 -m venv .venv-za
.venv-za/bin/python -m pip install /path/to/za_ldn_trade-VERSION-py3-none-any.whl
.venv-za/bin/za-ldn-trade doctor
.venv-za/bin/za-ldn-trade-gui
```

Windows（PowerShell）：

```powershell
py -3 -m venv .venv-za
.\.venv-za\Scripts\python.exe -m pip install C:\Downloads\za_ldn_trade-VERSION-py3-none-any.whl
.\.venv-za\Scripts\za-ldn-trade.exe doctor
.\.venv-za\Scripts\za-ldn-trade-gui.exe
```

パスに空白があれば引用符で囲みます。Linuxで無線も使う場合はPython 3.12以上の環境へ`'/path/to/za_ldn_trade-VERSION-py3-none-any.whl[live]'`を指定して導入します。GUI用のWindows環境へlive依存を入れてもLinux側の準備にはなりません。

### CLIで使うPython

ソースZIPのコマンド例は、**展開フォルダーを作業ディレクトリにして**`.venv-za/bin/python zatrade.py …`を実行します。setupは現在のシェルのPythonを切り替えないため、単に`python`と打つと別環境になる場合があります。

| 導入方法 | コマンドの先頭 |
|---|---|
| LinuxソースZIP | `.venv-za/bin/python zatrade.py` |
| WindowsソースZIP | `.\.venv-za\Scripts\python.exe zatrade.py` |
| Linux wheel | `.venv-za/bin/za-ldn-trade` |
| Windows wheel | `.\.venv-za\Scripts\za-ldn-trade.exe` |

[CLIリファレンス](../README_ZA.md)の例も、この対応で読み替えます。

## 最初のファイルを作る

1. 起動時の「**PA9編集**」画面で「**新規作成**」を選びます。無線設定は不要です。
2. 作成方法・種族・トレーナー名・個体の言語を指定します。TID/SIDは各0–65535の内部値で、ゲーム表示の6桁IDとは別です。「**新しいIDを生成**」はクリックしたときだけ新規値を入力し、ゲーム内の自分のIDを復元するものではありません。
3. 「**作成して編集**」を選び、内容を確認します。この時点では未保存です。
4. 固定された「**保存**」を押し、新規文書の保存先を指定します。`.pa9`は復号済み、`.epa9`／`.ea9`は暗号化出力です。

既存PA9は「開く」から読み込みます。「保存」は未適用入力も検査・適用して書き込み、元ファイルの置換前に確認します。「操作」の「適用」はメモリだけを更新し、「名前を付けて保存」は別の出力先を選びます。未保存の変更はタブの`*`で表示し、閉じる・開き直す際には保存／破棄／取消を確認します。

- storedは328バイト、partyは344バイト。通常保存は形式を維持し、party変換には明示確認と能力値計算が必要です。
- 新規文書は自動計算ON、既存文書は手動モード。「再計算」や自動計算ONはHP・状態異常も全回復します。
- 「構造チェック」はchecksum・既知の範囲などの確認です。完全な合法性、生成個体のゲーム読込み・実機交換は保証しません。

プリセット、ID、能力値計算の詳細は[PA9ガイド](PA9_CREATION.md)へ。解析タブも無線不要ですが、**キャプチャの採取は無線操作**です。

## 表示言語と操作

GUI上部の「日本語 / English」で切り替えます。処理や確認ダイアログを終えてから操作してください。待機中の切替は未適用入力・個体・タブ・ログ・接続欄を維持し、個体の言語IDや名前を書き換えません。

優先順位は明示の`gui --language`、`ZA_TRADE_LANG`、保存済み設定、OS言語です。日本語以外のOS言語は英語になります。ソースZIPなら次のように指定できます。

```sh
.venv-za/bin/python zatrade.py gui --language ja
.venv-za/bin/python zatrade.py gui --language en
```

保存する設定は表示言語だけです。既存設定を引き継ぐため、保存先のフォルダー名は改名後も変えていません。Windowsは`%APPDATA%\za-trade-lab\preferences.json`、Linuxは`$XDG_CONFIG_HOME/za-trade-lab/preferences.json`（既定`~/.config`）。壊れた設定は勝手に上書きしません。標準ファイルダイアログはOS言語、技術ログ／JSONキーは英語の場合があります。

**Ctrl+N** 新規 · **Ctrl+O** 開く · **Ctrl+S** 保存 · **Ctrl+Shift+S** 別名保存 · **Ctrl+L** 言語 · **F1** ヘルプ · **Ctrl+Q** 終了。

画面切替と言語・ヘルプ、保存／別名保存、交換／キャプチャの開始、停止・終了を固定しています。狭い画面では画面切替がコンパクトな一覧になります。**Alt+1〜5**で交換／PA9編集／キャプチャ／解析／ログへ移れます（確認ダイアログ中は切替しません）。

新規・既存文書とも主操作は「保存」です。「操作」に適用・構造チェック・再読込・変更を戻す・詳細表示をまとめました。基本画面は名前とレベルを中心にし、PID/ECなどの内部値とファイル詳細は必要時だけ表示します。自動計算・再計算は「能力」タブです。解析結果は読取り専用です。

種族・技・持ち物・特性の横の「選ぶ」から、日英の名前または番号で検索できます。候補を選択して確定します（キーボードは↓→Enter、Escapeで取消）。検索だけで選択を変えません。未知の値には数値入力も使えます。名前一覧は検索用であり、**その個体・タイトルで正規に使える候補の判定ではありません**。不正な数値は該当欄を表示・フォーカスし、個体へ適用しません。

編集画面ではフォームだけがスクロールし、ページ切替と文書操作は固定です。狭い・低いウィンドウではページ選択欄と「ファイル」メニューへ切り替わり、追加操作は「ファイル → 操作」、保存時の注意は「保存の注意」で確認できます。Ctrl+Tabは編集ページ内を移動します。

名前一覧は「前へ」「次へ」（Alt+←／→）で全件を閲覧でき、現在の値があるページから開きます。検索語を変えると先頭ページに戻り、勝手に項目を確定しません。長い名前には横スクロールを使えます。

小さい画面・高DPIではスクロールバーとTab／Shift+Tabで操作できます。ホイールは上下、Shift＋ホイールは左右、入力欄へのフォーカス移動でも表示位置を調整します。OSの倍率を下げる必要はありません。「停止」「終了」は主スクロール領域の外にあります。

## 無線の準備

**ここからは実験的な通信機能です。** 購入・接続前に[無線対応表](WIRELESS_COMPATIBILITY.md)を確認してください。1台の専用無線機を使う構成であり、2本必須ではありません。インターネット／SSH用の無線機は使わないでください。

### 準備済みの接続を使う（通常ユーザーGUI向け）

Linuxで無線処理だけを管理者として起動し、通常ユーザーのGUIから接続します。接続プログラムの名称が**Relay**です。Windowsはこの方式を使います。

無線を持つLinux側でPython 3.12以上と必要なOSツールを用意し、ソースZIPから実行します。

```sh
sh scripts/setup_za.sh --live
.venv-za/bin/python zatrade.py doctor --backend direct --radio
```

`PYTHON=python3.12 sh scripts/setup_za.sh --live`で初回のPythonを選択できます。ただし**既存venvのPythonは変わりません**。拒否された古いvenvは保全して別名へ移し、対応Pythonで作り直します。doctorは鍵読取り・スキャン・接続・設定変更をしません。複数PHYなら、一覧で確認した値を`--phy`へ指定してください。

必要条件を確認後、別々のターミナルで起動します。`phy0`、`wlan0`、鍵のパスは例です。ここでは対応する既存interfaceを再利用します。

```sh
# Linux terminal 1: 無線を担当するプロセスだけを管理者で起動
sudo .venv-za/bin/python -s -B zatrade.py relay-serve \
  --keys /path/to/your/prod.keys --phy phy0 --interface wlan0 --single-interface

# Linux terminal 2: 通常ユーザーGUI
sh scripts/start_za_gui.sh --backend relay --language ja
```

一時interfaceを作る対応構成では`--single-interface`を省略し、物理interfaceとは別の一時名を指定します。GUIで接続するだけではRelayの起動・昇格・driver導入は行いません。

GUIの「準備済みの接続を使う」は既定`127.0.0.1:24872`へ接続します。変更は詳細設定から。RelayはIPv4 loopback限定で、同じOSのlocal processを信頼します。非信頼ユーザーと共有する環境では起動せず、LAN／Internetへ直接公開しません。別Linux機へはSSH転送を使います。

```sh
ssh -N -L 24872:127.0.0.1:24872 USER@LINUX_HOST
```

鍵はLinux側だけに置き、GUIへ転送しません。任意BSS補助も無線を担当するLinux側で[ビルド・指定](BSS_HELPER.md)します。未使用なら空欄のままです。

### このPCのWi-Fi（Linux直接接続）

Linuxの初期表示です。通常ユーザーGUIで使うなら、上の準備済み接続方式へ切り替えてください。直接接続の実行にはlive依存と無線操作権限が必要で、一覧が見えることだけでは実行できません。

1. 専用無線機を接続し「一覧を更新」。「**使うWi-Fiアダプター**」から選びます。PHYの手入力は不要です。
2. 鍵を「参照」で指定し、必要なら「環境チェック → 無線詳細（このPC）」を開きます。一覧更新・選択は通信を始めません。
3. 開始時は機器の同一性・必要機能・経路/IP・使用状態を再確認し、不明・使用中・非対応なら停止します。

1台だけでも自動選択しません（起動時の明示`--phy`が一意に一致する場合を除く）。並び替え・言語切替では選択を保持し、抜差し・入れ替わりでは解除します。次回起動へは保存しません。「使用中／無効化中／未診断」は互換性の証明ではありません。

詳細設定に表示名・ゲーム版、選択PHYの確認表示、一時interface名、既存Wi-Fi再利用をまとめています。再利用「はい」は選択した実interface、「自動」はdriver別の既定方式です。通常は変更不要です。ローカル一覧・診断は**接続先Relayの無線機を調べるものではありません**。

### Windows / WSL2

WSLの仮想Ethernetでは代用できません。専用USB Wi-FiをWSLへ渡し、WSL側に対応driver/firmwareを用意する必要があります。[MicrosoftのUSB手順](https://learn.microsoft.com/windows/wsl/connect-usb)と[CLIリファレンスのWSL手順](../README_ZA.md#wsl2を同じpcで使う)を参照してください。USB列挙だけでPHY・通信を保証しません。

Relay準備後、Windowsの`Start-za-ldn-trade.cmd`からGUIを開きます。WSLのdriver/kernel対応、接続先への到達性は別途確認が必要です。この配布版のWindows/WSL実行は未検証です。

## 交換する

大切な個体や唯一のセーブでは試さず、試験用データから始めてください。自動承認は既定OFFです。

1. 実機Z-A **2.0.2**でローカルのボックス交換を開き、8桁の通信パスワードで待受けます。
2. GUIへ同じパスワードを入力します。既定値はありません。
3. 完全な**344バイトparty PA9**と、新しい受領ファイル名を指定します。328バイトのゼロ埋めは代用になりません。
4. 「交換を開始」。実機側でも渡してよい個体を選択・確定します。
5. PCの確認画面で相手個体を見てから承認します。既定は「いいえ」。承認後は取り消せない場合があります。
6. 保存同期・PC保存・後片付けを待ちます。標準の制限時間は300秒です。実機の交換演出・セーブ表示が終わってから、受領ファイルとゲームの状態を確認します。

## 停止と結果の確認

「停止」は協調停止を要求します。処理中に閉じる場合も確認後に停止し、無線の復旧を待ちます。強制終了・USB抜去で後片付けを打ち切らないでください。

**「結果未確定」「FinalAgreement後」なら、同じ交換を再実行しないでください。** タイムアウトや停止はゲーム側の巻戻しを意味しません。実機と、結果に表示された受領／保全ファイルを先に確認します。復旧失敗時も連続試行せず、元の状態と証拠を保全してください。

起動・外部変更・設定の問題は[困ったとき](TROUBLESHOOTING.md)へ。ログは公開前に通信アドレス・コード・名前・私有パスを除いてください。鍵・セーブ・個体・ROM・raw captureは添付しません。

### 受領ファイルとエディターの保存保護

交換ごとに新しいファイル名を使ってください。新規保存は、承認後に別ファイルが現れても置換しない原子的な公開処理を使います。エディターと交換処理は同一ユーザー・ホスト・一時ディレクトリ設定でパス別の保存ロックを共有し、承認済みの既存出力はロック内で内容も再確認します。ただし、別ソフト・別ユーザー/ホスト・異なる一時ディレクトリ設定のプロセスによる既存ファイルの同時変更まで、完全な比較付き置換（CAS）で防ぐものではありません。

承認した保存先が使えなければ、一意な`*.recovered-*`へ保全し、その保存も失敗した場合はfsync済みの書込み前コピーを保持します。指定した名前ではなく、**結果に表示される実際の保存先と警告**を確認してください。ワーカーが終了済みでも、GUIは取引結果を表示してから閉じます。ダイアログ表示に失敗した結果を無言で確認済みにすることもありません。

キャプチャ解析の停止は空行・対象外のメタデータも含め、長さ制限付きの各入力行で確認します。

### 入力制限とローカル処理の失敗からの復帰

PA9検査は344バイト、オフラインのコマンド入力は64KiB（matrixは1200バイト、party PA9は344バイト）、保存先の同一性検査は1MiBまでです。キャプチャ全体の容量制限ではありません。キャプチャは1行64KiB、JSONの入れ子は設定ファイルと共通で64階層まで。設定ファイルは64KiBまでです。名前付きパイプ・デバイスや危険なファイル差し替えはopenで待ち続けず拒否します。キャプチャ/CLI検査で通常のシンボリックリンク入力は使えますが、エディター対象・設定ファイルでは拒否します。

壊れた言語設定は勝手に上書きせず、起動時はOSの言語へフォールバックします。その場の表示切替は可能ですが、選択を保存するには不正な設定ファイルを修復するか別名へ移してください。スレッドを起動できなかった場合は該当ボタンを復帰させます。未表示の結果を新しい処理で置き換えず、終了時はこのウィンドウのTkコールバックを取り消します。

通常ファイルのI/OでもOS内で停止する場合があり、協調停止は即時中断の保証ではありません。別機能の生ダンプ`scan`は入力全体をメモリへ読み、容量に応じたRAMが必要です。キャプチャのストリーミング解析とは異なります。

GUI起動や依存チェックの成功は、無線接続・ゲーム交換の成功を意味しません。`doctor --radio --json`でも`live_connection_tested`は常にfalseです。診断0は必要条件のみ、2は不足/使用中、3は未判定/選択待ち。確認できない条件を成功扱いしません。詳細は[無線対応表・診断](WIRELESS_COMPATIBILITY.md)。

</details>
